# Next SEKAI Editor

Next SEKAI Editor is a free, open-source chart editor for Sonolus.

[Open the Editor](https://nse.qwewqa.dev/)

## Local Development

Use the Node.js version in `.node-version`.

```sh
npm ci
npm run dev
```

### Preview Assets

The web editor uses the Next SEKAI skins, particle effects and sound effects from
coconut.sonolus.com. The five packages are listed in `deployment/preview-assets.lock.json`.

Before starting the dev server, `npm run dev` prepares the packages in `public/resource/`.
It keeps packages that match the lock file and copies missing or outdated packages from
`node_modules/.cache/nse-preview-assets/` when a matching cached copy is available.
Otherwise, it downloads and verifies them against the lock file.

To update the packages, run `npm run refresh:preview-assets`. This rewrites the lock file
using coconut.sonolus.com. Use `PREVIEW_<NAME>_URL` to select a different item. Commit the
updated lock file. The next `npm run dev` prepares the new packages.

If a package is still missing or does not match the lock file, the dev server prints a
warning and the editor uses only the Built-in assets, as the apps do. To use only the
Built-in assets during development, run `NSE_SKIP_PREVIEW_ASSETS=1 npm run dev`.

To prepare the packages manually, as CI does:

```sh
node --input-type=module -e "const { stagePreviewAssets } = await import('./scripts/release-assets.mjs'); await stagePreviewAssets(process.cwd(), 'public')"
```

`npm run build:release` builds `dist` with preview assets.

## Built-in Assets and the Native Build

The Built-in preview assets in `public/builtin/` are generated from `builtin-assets/`
with `npm run build:builtin-assets` and committed to the repository.
`npm run check:builtin-assets` rebuilds them and compares the generated bytes with the
committed files.

`npm run build:native` builds the frontend for the apps in `dist-native/`, using a
temporary public folder containing only approved files. `npm run check:native-bundle`
checks the result for web-only files and references. These two commands do not require Rust.

## Browser Compatibility

The minimum supported versions are Chrome 106, Edge 106, Firefox 105, Safari 17 and
iOS 17.

The production build targets Chrome 106, Edge 106, Firefox 105, Safari 16 and iOS 16
(the October 2022 baseline). Keep these targets explicit in the Vite configuration when
updating Vite; its [default build targets](https://v8.vite.dev/config/build-options) can
change between major releases.

Build targets cover syntax. The editor also requires IndexedDB,
`navigator.storage.estimate`, Web Locks, OffscreenCanvas and `structuredClone`.
At startup, `public/gate.js` displays an unsupported-browser page if any of these APIs
are unavailable. These requirements raise the minimum Safari and iOS versions to 17.

Other browser APIs use feature detection or fallbacks. Notes are drawn without
`roundRect` when it is unavailable, and viewport sizing uses `vh` when dynamic viewport
units are unavailable.

```sh
npx playwright install firefox webkit
npm run test:compatibility
```

This builds the production UI and runs compatibility tests in Firefox, WebKit and
mobile WebKit. The checks cover importing and exporting, touch context menus, scaling
and elevation layouts in both orientations. They also cover WebGL rendering in the
editor, decoding and rendering preview textures, internal copy and paste when clipboard
permission is denied, audio scheduling and waveform rendering.

Playwright 1.27.1 provides archived Chromium 107.0.5304.18 and Firefox 105.0.1 binaries.
These versions are close to the minimum supported versions and can run the production
UI checks. Its WebKit 16.0 is below the minimum and displays the unsupported-browser
page. Use archived binaries only for isolated local testing.

[Playwright WebKit](https://playwright.dev/docs/browsers#webkit) tests the browser engine
used by Safari. Safari itself and physical iPhones still need separate testing.
Windows WebKit lacks Web Audio, so audio tests are skipped there. The production UI
tests provide an audio stub on Windows, but also skip WebKit builds that lack
OffscreenCanvas. Linux CI runs the audio tests without the stub.

Test iOS Safari on a device for audio activation, clipboard permissions, file pickers
and downloads, resizing of the browser toolbars and safe areas.
